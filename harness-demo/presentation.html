The whole talk in one line

The model is fixed.
The harness is your leverage.

Same model. Same agent. We'll only change the context around it — and watch behavior, speed, and correctness change completely.

Say this slowly. Everything in the demo holds the task and agent constant; the harness changes.

What is a "harness"?

CONTEXTUAL HARNESS naming · docs · skills · tools · MCP · prompts
AGENT the loop: plan → act → observe
SCAFFOLD tools, parsing, retries, sandbox
MODEL fixed weights — same for everyone

Model — the weights. You don't change them.

Scaffold — the plumbing that lets it act.

Agent — goal + loop.

Contextual harness — what's true about this repo. This is the layer we engineer. This is the talk.

Use this slide to define the stack. The rest of the talk zooms into the contextual harness: names, docs, tools, prompts, MCP.

First, demystify it

A coding agent is not magic

To change code, it must first find it.

search files → grep words → read → edit → repeat

Everything we do to the harness just makes one of those steps cheaper — or skips it.

Frame the agent as a loop over search and observation, not as magic. That makes the later results intuitive.

Concept 1

File names are a search index

bad/

utils/u.js

glob **/*permission* → 0 hits

good/

utils/user-permissions.js

glob **/*permission* → 1 hit

Same code. Same model. A searchable name turns discovery into a one-line lookup.

Land the phrase: file names are an index for agents. This is context engineering, not prompt wording.

Concept 2 · clean code is harness

Variable & value names matter too

cryptic

const d = { bhaskar: { lv: "r" } }

grep "permission|level|read" → 0 hits

clean

const userPermissions = {
  bhaskar: { permissionLevel: "read" } }

→ 5 hits

The model reads English. Your variable names are the search terms. lv:"r" is invisible to the query the agent runs.

Keep this short. It supports the naming argument and broadens it beyond filenames.

Concept 3

AGENTS.md / CLAUDE.md kills the cold start

Every agent starts knowing nothing about your repo. The startup doc is the one file it reads first.

without/

explores acl.js vs cache.js, must guess which is real

with/

doc says "edit utils/acl.js" → goes straight there

Write it once. It pays back on every task forever. Cheapest harness upgrade there is.

Call this the repo's cold-start map. Agents need a map before they need cleverness.

The levers — all of it is context

LeverWhat it buys you
Namingthe repo becomes its own search index
Docs (AGENTS.md)skips the discovery phase
Skills / toolsencodes senior-engineer knowledge once
MCPagent reads live ground truth, doesn't guess
Promptsstandardizes how a task is done, every time

None of these touch the model.

Connect the small demo to larger systems: MCP is the same idea applied to live databases, tickets, browsers, docs, or internal APIs.
