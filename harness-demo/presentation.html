Act 1How an agent works

A coding agent is a loop around a model

ContextSystem prompt, AGENTS.md, tool list, your message, every tool result so far.harness + you
ModelReads all of it and writes the next message: text, or a tool call.fixed weights
Tool callgrep "bhaskar", read users.js, edit …just text
Harness runs itExecutes the tool, appends the output to the context.harness
repeat until the model stops calling tools

You can't change the weights. Everything else on this slide is the harness, and you can change all of it.

Say: "The model never touches your disk. It writes text that says 'grep for bhaskar'. The harness runs grep and pastes the result back. Then the model gets called again with everything so far."

opencode, pi, Claude Code, Cursor: all the same loop. They differ in the system prompt, the tools, and what they put in the context.

Act 3Practical

What to put in AGENTS.md

Put in

  • Where the source of truth lives for things people ask to change
  • What not to edit: generated files, snapshots, legacy copies
  • Build, test and lint commands, and your helper scripts
  • How to verify a change

Leave out

  • Long architecture essays
  • Anything the code already says clearly
  • Stale facts: review it like code

It is re-sent on every turn, so every line costs tokens on every task.

  1. cat concepts/04-coldstart-doc/with/AGENTS.md

Bridge: "Docs and tools encode knowledge someone already has. What if nobody wrote it down? That's act 4."

Act 4Thinking, fast and slow

Two kinds of work in every task

System 1 · fast, shallow, many

  • Is this a question or a change?
  • Which of these 12 files is it?
  • Which 3 of these 14 tools does it need?
  • Did that command fail?

System 2 · slow, deep, few

  • Read this file closely
  • Write the edit
  • Explain why it works
  • Plan a refactor

Today the big model does both. Most of s1 was System 1 work at System 2 prices.

Kahneman's terms: System 1 is quick and intuitive, System 2 is slow and deliberate. A harness can give each its own model.

Act 4A System 1 model

Clef-flash: a model that only decides

  • A decision model: you send a state and typed questions, it returns a probability for every allowed answer.
  • No generated text, so nothing to parse and no invented options.
  • 9B parameters, open weights (Apache 2.0), hosted on Cloudflare Workers AI. Up to 64 questions per request.
  • Cloudflare quotes a 38.8 ms median. Released 1 October 2026.
POST …/ai/run/@cf/cloudflare/clef-flash
{ "state": "User request: Change bhaskar's …",
  "questions": {
    "intent": { "type": "choice",
      "instructions": "What does the user want?",
      "criteria": { "question": "…",
                    "change": "…", "run": "…" } },
    "risky": { "type": "noul",
      "instructions": "Could a mistake break prod?" }
} }

→ probabilities per answer (shape simplified)
  intent  question 0.04  change 0.93  run 0.03
  risky   0.81
  1. node scenario-5/tools/system1.mjs

Clef (27B) is the larger sibling at about 209 ms median. Pricing at launch: $0.09 per million input tokens for Clef-flash, output not billed.

Question types: choice (2–255 options), noul (yes/no), score (ordered levels).

If there are no Cloudflare credentials, the tool prints "offline stand-in": a keyword heuristic so the demo still runs. Say so plainly when it happens.

Act 4Where a fast model plugs in

Three places for System 1

Inside the harness

Session titles, summaries, compaction, safety checks on commands. Many harnesses already use a small model here.

As a subagent

A fast chat model explores and reports back a short answer. Claude Code's Explore subagent runs on Haiku; opencode sets a model per agent.

As a decision tool

Route, select tools, rank, check: typed answers with probabilities. What we just ran.

Let System 1 decide what System 2 looks at.

Rule of thumb: wide and shallow goes to System 1, narrow and deep stays with System 2.

Act 5Takeaways

Five things to take back to your repo

  1. An agent is a loop: search, read, act. Most turns are finding.
  2. Names are the index. Clean code is agent infrastructure.
  3. AGENTS.md is the cheapest upgrade. It is in every prompt.
  4. Tools encode what you know. A fast model adds judgment on the fly.
  5. "Done!" isn't proof. Verify the diff.

Likely questions:

  • Isn't this prompt engineering? The prompt never changed. We changed what the agent finds: names, docs, tools.
  • Why not a bigger model? In s1 a bigger model still faces four plausible files and nothing that says which is live. It guesses better; it still guesses.
  • Doesn't AGENTS.md go stale? Yes, like any doc. Keep it short and review it in PRs. A tool like s4's or s5's can't drift as easily.
  • What does System 1 cost? Clef-flash at launch: $0.09 per million input tokens, nothing for output. One rank call here is a few hundred tokens.
  • Can System 1 be wrong? Yes. It returns probabilities, so the harness can fall back to normal search when the top answer is below a threshold (s5 uses 0.5).
